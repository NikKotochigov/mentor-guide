# Поиск с гонкой запросов

Время: 30-40 минут (около 15-20 на код, остальное на обсуждение).

Компонент поиска пользователей. На каждый ввод уходит запрос. В `App.tsx` уже есть рабочий, но бажный вариант. `fetchUsers(query, signal)` в том же файле уже поддерживает `AbortSignal`. Ответы сервера приходят в случайном порядке (300-1500 мс).

## Баги, на которые жалуется QA

1. Быстро печатаем "react" - иногда в списке результаты для "rea", хотя в инпуте уже "react".
2. На каждую букву летит запрос, бэкенд ругается на нагрузку.
3. Если очистить инпут, остаются старые результаты.
4. Ушли со страницы во время запроса - в консоли warning или ошибка.

## Что сделать

Найти причины багов и исправить:
- показывать результаты только для актуального query;
- дебаунс 300 мс;
- пустой query - пустой список без запроса;
- отменять запрос при смене query и при unmount;
- показать состояния loading и error.

Код пиши в `UserSearch` в `App.tsx`, `fetchUsers` менять не нужно. Чтобы открыть в StackBlitz, создай проект Vite React TypeScript и замени `src/App.tsx` этим файлом.

## Как проверить

- Быстрый ввод "react": в списке должны остаться результаты именно для "react", а в консоли видно, что промежуточные запросы отменились.
- Запрос уходит не на каждую букву, а после паузы в 300 мс.
- Очистка инпута сразу очищает список и не делает запрос.
- `AbortError` не показывается как ошибка пользователю.
